# TG Sender

Многопользовательский Telegram-бот: каждый подключает свой аккаунт, ищет публичные
сообщества, отмечает получателей и отправляет свой текст от своего имени.
Python 3.11, aiogram, Telethon, aiohttp, SQLite, Fernet. Один процесс сервиса.

## Что доступно

- Вход внутри Telegram через Mini App: номер → код → 2FA, если включена.
- Повторный вход не нужен: сессии хранятся в зашифрованном виде на сервере.
- Telegram ID из проверенной подписи Mini App должен совпадать с подключаемым аккаунтом.
- Внешний поиск по теме/названию исключает чаты, в которых аккаунт уже состоит.
- Категории «Программисты», «Работа», «Криптовалюты», «Бизнес» задают тематические запросы.
- Отдельно доступны свои чаты и папки `https://t.me/addlist/...`.
- Список с галочками обновляется в одном сообщении: 8 результатов на странице,
  выбор всех доступных результатов или отдельных чатов, исключения, просмотр выбранных.
- Обычный текст до 4096 символов Telegram, предпросмотр, подтверждение, статус и остановка.
- Отдельные черновики, выбор, журнал и лимиты для каждого пользователя.
- Отключение аккаунта останавливает его отправку и удаляет сессию и черновик из активной БД.

**Публичность не даёт права публикации.** В каналах нужны права администратора на посты.
В некоторых группах обсуждений допускается отправка без вступления (`join_to_send=false`),
в остальных требуется вступление. Заблокированные получатели помечены 🔒 и не выбираются.
Окончательные права проверяет Telegram при отправке. Автовступление и обход ограничений отсутствуют.

Публичный поиск ограничен выдачей Telegram — до 50 результатов на запрос, без гарантии
полноты и без полноценного каталога категорий. Свои диалоги загружаются до 1000 записей.
В одной рассылке можно выбрать до 1000 получателей. Отметки из разных запросов сохраняются.
После перезапуска выбранные ID и текст остаются, но перед отправкой нужно заново загрузить
соответствующие результаты, чтобы восстановить доступные получатели.

Доставка всем «за одну секунду» не реализуется: сообщения идут последовательно с интервалом
5 секунд по умолчанию (минимум настройки — 3 секунды). Лимиты Telegram и правила сообществ
обязательны. При FloodWait/slow mode отправка останавливается, новые запуски блокируются
на требуемое время. При PeerFlood отправка также останавливается. Тайм-аут или неизвестный
результат не повторяются автоматически — нужно проверить фактическую доставку.

## Настройка сервиса

Пользователям не нужны свои API-ключи: владелец сервиса один раз получает пару приложения.

1. Откройте https://my.telegram.org/apps, войдите по номеру и создайте приложение
   в API development tools (произвольные App title, Short name, платформа Desktop).
2. Впишите `API_ID`, `API_HASH` и `BOT_TOKEN` в локальный `.env`.
3. Если `.env` ещё нет, скопируйте `.env.example`, не перезаписывая существующий файл.
4. Установите зависимости и сгенерируйте ключ хранения:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install --only-binary=:all: --no-binary=pyaes -r requirements.txt
.venv\Scripts\python.exe -m bot.init_secrets
```

Команда записывает `SESSION_ENCRYPTION_KEY` только в `.env`, не печатает его и не заменяет
существующий. Сохраните резервную копию ключа отдельно от базы. Потеря или замена ключа
сделает сохранённые сессии и черновики недоступными. Fernet защищает содержимое на диске;
работающий сервер с ключом имеет доступ к сессиям. Оператор сервиса должен защищать хостинг,
окружение и резервные копии. ID пользователей и технический журнал доставки не зашифрованы.

`BOT_TOKEN`, `API_HASH`, ключ шифрования, session и коды входа не публикуйте.
Опубликованный в переписке токен перед деплоем перевыпустите через @BotFather.
Старые `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `OWNER_TELEGRAM_ID`, `TELEGRAM_SESSION`
в новой версии не используются: общего логина/пароля и общего отправителя больше нет.

## Render: HTTPS Web Service + диск

1. Загрузите исходники в свой Git-репозиторий без `.env`, `data/` и session-файлов.
2. Создайте Blueprint в Render из `render.yaml`. Ресурсы платные: Web Service Starter + диск 1 GB.
3. Заполните секреты `BOT_TOKEN`, `API_ID`, `API_HASH`, `SESSION_ENCRYPTION_KEY`
   значениями из локального `.env` без внешних кавычек dotenv.
4. Render автоматически задаёт `RENDER_EXTERNAL_URL`; он используется как HTTPS-адрес
   формы. Для своего домена задайте `PUBLIC_BASE_URL=https://ваш-домен` без пути и завершающего `/`.
5. `DATA_DIR=/var/data` и диск сохраняют SQLite между рестартами. Ключ не меняйте при деплоях.
6. Остановите локальный polling-процесс перед запуском Render. Нужен один экземпляр сервиса.
7. Откройте `/start` в боте → «Подключить мой Telegram». Пройдите вход в Mini App,
   закройте форму и нажмите «Проверить подключение». Затем поиск → выбор → текст → предпросмотр.
8. Первый реальный запуск проверьте в собственной тестовой группе, затем двумя аккаунтами
   проверьте независимость настроек. Такой live-тест ещё не выполнен.

Форма должна открываться кнопкой бота внутри Telegram. Обычный браузер без подписанной
`initData` не допускается к API. HTTPS обязателен, `PUBLIC_BASE_URL` — точный origin
для проверки запросов. Cookies и CORS для входа не используются.
Срок подписи и попытки входа ограничены; после 5 ошибок блокировка на 15 минут.
Повторный запрос кода доступен не чаще раза в минуту. Код и 2FA не сохраняются в БД.
Через 5 минут форму нужно открыть заново, если вход не завершён.

По умолчанию в памяти до 50 активных пользователей и до 3 параллельных отправителей,
настройки — `MAX_ACTIVE_USERS`, `MAX_CONCURRENT_SENDERS`. Неактивные контексты освобождаются
через 15 минут, сессии остаются в БД. Число зарегистрированных сессий этим не ограничивается.
Ожидание свободного отправителя — максимум 10 минут. Нагрузочное тестирование не проводилось;
эти лимиты являются настройками, а не обещанием производительности конкретного тарифа.
SQLite с диском рассчитан на один процесс. Для горизонтального масштабирования нужны
общая БД и очередь; увеличение `numInstances` в этой реализации не поддерживается.

Запуск после настройки доступного HTTPS-домена:

```powershell
.venv\Scripts\python.exe -m bot
```

Приложение слушает `PORT` (по умолчанию 10000). `/healthz` — проверка жизни HTTP-сервера,
она не подтверждает доступность Telegram. Webhook бота должен быть отключён для polling.
Приложение не удаляет его автоматически. Переменные окружения имеют приоритет над `.env`.

## Хранение и восстановление

Сессии и черновики шифруются с привязкой к Telegram ID. SQL-операции журнала ограничены
тем же ID. Изменение клиентского user_id не даёт доступа к чужим данным.
На диске создаются таблицы `v2_*`. Прежние одноаккаунтные таблицы не удаляются и не
привязываются автоматически к пользователю; прежний общий журнал не показывается.

При рестарте незавершённые рассылки отмечаются прерванными; возможная доставка становится
неизвестной, автоматического продолжения нет. Повторная новая рассылка может повторить
уже доставленный текст. Перед деплоем остановите отправки, перед изменениями схемы
создайте snapshot диска. Для отката используйте предыдущий deploy и совместимый snapshot.
Удалённая сессия может оставаться в старых резервных копиях: отзыв сеанса в Telegram
защищает от повторного использования. Если отключение не подтверждено сетью, бот попросит
завершить сеанс вручную через Telegram → Настройки → Устройства.

## Структура и проверки

```text
bot/
  __main__.py       # HTTP-сервер и polling, завершение
  config.py         # настройки сервиса
  runtime.py        # изолированные контексты пользователей, лимиты и очистка
  security.py       # проверка initData и шифрование Fernet
  auth_web.py       # API формы входа, ограничения и HTTP-защиты
  account.py        # вход, свой аккаунт, публичный поиск и права
  panel.py          # меню, категории, страницы, выбор, подтверждение
  sender.py         # очередь отправки, лимиты и остановка
  store.py          # SQLite, отдельные данные каждого пользователя
  init_secrets.py   # генерация локального ключа хранения
  web/             # форма входа без сборщика frontend
tests/
render.yaml
```

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m pip check
```

Проверяются поддельные и устаревшие подписи, чужие аккаунты и записи, изоляция двух
отправителей, ограничения попыток/запроса кода, состояния кода и 2FA, выбор доступных
получателей, обновление одного сообщения, одноразовое подтверждение, снимок списка,
остановка, FloodWait, неизвестный результат и восстановление БД.
Сетевые операции Telegram заменены тестовыми клиентами. Реальная авторизация, выдача
поиска, отправка и деплой Render не проверены без API-ключей и аккаунтов пользователей.
Визуальная проверка формы в браузере не проведена: подключённый браузер недоступен.

Зависимости зафиксированы в `requirements.txt`, прямые — в `requirements.in`.
Для pyaes 1.6.1 доступен исходный архив: стандартный setup.py проверен, сборка разрешена
только для этого пакета. Остальные пакеты устанавливаются из wheels.
Telegram WebApp SDK загружается с официального домена telegram.org.

Документация: [Mini Apps и проверка подписи](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
[права и join_to_send](https://core.telegram.org/constructor/channel),
